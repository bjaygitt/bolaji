## 2.1 Arithmetic that wraps around

A clock is the best introduction to cryptographic arithmetic. If it is 10 o'clock and you add 5 hours, you get 3 o'clock, not 15. The numbers wrap around after 12. Mathematicians write this as:

```
10 + 5 = 3 (mod 12)
```

and say "10 plus 5 is congruent to 3, modulo 12". The number after "mod" is the **modulus**. Working "mod n" means you only keep the remainder after dividing by n. So `17 mod 5 = 2`, because 17 divided by 5 is 3 with remainder 2.

All the usual operations work in modular arithmetic:

- **Addition:** `(4 + 9) mod 11 = 13 mod 11 = 2`
- **Multiplication:** `(4 × 9) mod 11 = 36 mod 11 = 3`
- **Exponentiation:** `3^4 mod 7 = 81 mod 7 = 4`

Why does cryptography love this? Two reasons. First, numbers stay a fixed size: no matter how many operations you do, the result is always between 0 and n minus 1, which computers handle efficiently. Second, wrapping around scrambles the relationship between input and output. Knowing that `3^x mod 7 = 4` does not easily tell you x, because the results jump around instead of growing steadily.

### Fast exponentiation

Public-key cryptography raises numbers to enormous powers, with exponents hundreds of digits long. Multiplying 3 by itself that many times would never finish. Instead, computers use **square-and-multiply**: write the exponent in binary, square at every step, and multiply in the base whenever the binary digit is 1. Computing `3^13 mod 7`:

```
13 in binary = 1101
start with 1
bit 1: square (1) then multiply by 3  -> 3
bit 1: square (9 mod 7 = 2) then multiply by 3 -> 6
bit 0: square (36 mod 7 = 1)          -> 1
bit 1: square (1) then multiply by 3  -> 3
result: 3^13 mod 7 = 3
```

The number of steps grows with the number of digits in the exponent, not its size, so a 3072-bit exponent takes a few thousand steps instead of an impossible number.

> **In practice.** The square-and-multiply pattern is also a classic source of leaks. If "multiply" steps take measurable time, an attacker timing the operation can read the exponent's bits, which is the private key. Production libraries use **constant-time** versions that do the same work for every bit (Chapter 9).

### Inverses and the greatest common divisor

In ordinary arithmetic, dividing by 4 means multiplying by 1/4. In modular arithmetic, "dividing" means multiplying by an **inverse**: a number that gives 1 when multiplied. Mod 11, the inverse of 4 is 3, because `4 × 3 = 12 = 1 (mod 11)`.

An inverse exists only when the number and the modulus share no common factor, that is, when their **greatest common divisor (gcd)** is 1. The ancient **Euclidean algorithm** computes gcds quickly, and its extended version finds inverses. RSA key generation (Chapter 7) depends on it.

## 2.2 Primes and why factoring is hard

A **prime** is a whole number greater than 1 whose only divisors are 1 and itself: 2, 3, 5, 7, 11, 13 and so on. Every whole number breaks down into a unique product of primes, for example `60 = 2 × 2 × 3 × 5`.

Two facts about primes power a large part of cryptography:

1. **Multiplying two large primes is easy.** A computer multiplies two 1536-bit primes in a fraction of a millisecond.
2. **Splitting the result back into its primes is hard.** For a 3072-bit product, no known method on classical computers can find the factors in any useful amount of time.

This one-way behaviour is the **factoring problem**, and RSA is built on it. Note the word "known". Nobody has proved factoring is hard. It is believed hard because the best mathematicians have tried for centuries. That belief has a sharp exception: a large quantum computer running **Shor's algorithm** could factor efficiently (Chapter 25).

### Finding large primes

If factoring is hard, how do we find primes in the first place? We do not factor anything. We pick a random large odd number and run a **probabilistic primality test**, such as Miller-Rabin, which quickly answers "definitely composite" or "almost certainly prime". Repeating the test enough times pushes the chance of error below one in 2^128. Primes are common enough among large numbers that a few hundred random tries usually find one.

## 2.3 Groups: the structure under everything

A **group** is a set of things plus one operation that behaves nicely. Formally, the operation must combine any two members into another member, have an identity element that changes nothing, give every member an inverse, and be associative. You do not need to memorise the definition. What matters is the idea: a group is a closed world where you can combine elements as many times as you like and always stay inside.

Two groups appear constantly in this book:

- **The multiplicative group mod a prime p.** The numbers 1 to p minus 1, combined by multiplication mod p. Used by classic Diffie-Hellman and DSA.
- **The points on an elliptic curve.** Combined by a geometric "point addition" rule. Used by ECDH, ECDSA and EdDSA.

### Generators and order

In some groups, one element can produce every other element by repeated combination. That element is called a **generator**. Mod 7, the number 3 is a generator:

```
3^1 = 3, 3^2 = 2, 3^3 = 6, 3^4 = 4, 3^5 = 5, 3^6 = 1 (mod 7)
```

Every number from 1 to 6 appears exactly once. The number of distinct elements a generator produces before repeating is its **order**. Cryptographic designs choose groups whose order is a large prime, or contains one, because small orders let attackers break the problem into easy pieces. Careless choices here caused real attacks, such as small-subgroup attacks, which is one reason modern standards fix the groups for you.

## 2.4 The discrete logarithm problem

In the table above, going forward is easy: given 3 and 4, computing `3^4 mod 7 = 4` takes one step. Going backward is the hard direction: given that `3^x mod 7 = 4`, find x. This is the **discrete logarithm problem**, and with a 3072-bit prime, it is as hard to reverse as factoring.

Diffie-Hellman key exchange (Chapter 8) uses it like this. Alice picks a secret a and publishes `g^a`. Bob picks a secret b and publishes `g^b`. Each raises the other's public value to their own secret, and both reach `g^(ab)`. An eavesdropper sees `g^a` and `g^b` but cannot compute `g^(ab)` without solving a discrete logarithm.

## 2.5 Finite fields

A **field** is a set where you can add, subtract, multiply and divide (except by zero), with all the familiar rules holding. A **finite field** is a field with a finite number of elements. Two kinds matter:

- **Prime fields, written GF(p).** The numbers 0 to p minus 1 with arithmetic mod a prime p. Elliptic curves such as P-256 and Curve25519 are defined over prime fields.
- **Binary fields, written GF(2^n).** Elements are strings of n bits, and addition is bitwise XOR. AES does its internal mixing in GF(2^8), the field of all byte values (Chapter 4), and the GCM mode computes its integrity tag in GF(2^128) (Chapter 5).

The useful intuition: a finite field is a set of fixed-size values with arithmetic that never overflows and always has a clean answer, which is exactly what both hardware and cryptographers want.

## 2.6 Elliptic curves, without the pain

An **elliptic curve** is the set of points (x, y) satisfying an equation such as:

```
y^2 = x^3 + ax + b
```

Over ordinary real numbers, this draws a smooth curve. Cryptography uses the same equation over a finite field, so the "curve" becomes a scattered set of points, but the rules carry over.

The key trick is **point addition**. Draw a line through two points on the curve. It hits the curve in exactly one more point. Reflect that point across the x-axis, and you have the "sum" of the first two. Adding a point to itself uses the tangent line instead. With this rule, the points form a group.

Now the hard problem. Pick a starting point G and a secret whole number k. Computing `kP`, meaning G added to itself k times, is fast using the same doubling trick as square-and-multiply. But given G and the result, finding k is the **elliptic curve discrete logarithm problem (ECDLP)**, and it is much harder than the ordinary discrete logarithm for the same size of numbers. That is why a 256-bit elliptic curve key matches a 3072-bit RSA key.

The curves you will meet are standardised and named:

| Curve | Used in | Notes |
| --- | --- | --- |
| P-256 (secp256r1) | TLS, certificates, ECDSA, many HSMs | NIST curve; the most widely deployed |
| P-384 | High-assurance government and financial uses | NIST curve; required by some regulated profiles |
| Curve25519 / X25519 | Key exchange in TLS 1.3, SSH, Signal, WireGuard | Designed to be fast and hard to implement wrongly |
| Ed25519 | Signatures in SSH, software signing, many modern protocols | Edwards form of Curve25519 |

## 2.7 A first look at lattices

Everything above, factoring and both discrete logarithm problems, falls to Shor's algorithm on a large quantum computer. The replacement algorithms standardised by NIST in 2024 rest mostly on a different kind of mathematics: **lattices**.

Picture a sheet of graph paper stretched and skewed so its grid lines run at odd angles. The crossing points form a lattice. In two dimensions, finding the crossing point closest to some random spot is easy. In 500 or 1000 dimensions, with a deliberately awkward description of the grid, it becomes extremely hard, for classical and quantum computers alike, as far as anyone knows.

The specific problem behind ML-KEM and ML-DSA is called **Learning With Errors (LWE)**. In words: you are given many equations that would be easy to solve, except that each one has a small random error added. The errors make the system unsolvable in practice. Chapter 26 builds on this idea. For now, remember one sentence: **post-quantum cryptography replaces "hard to factor" and "hard to find the logarithm" with "hard to find the secret hidden under small noise".**

## Lab: check the mathematics yourself

You only need Python 3, which is already installed on most computers. Open a terminal and type `python3`.

**1. Modular arithmetic and fast exponentiation.** Python's built-in `pow` takes a third argument, the modulus, and uses square-and-multiply internally:

```python
pow(3, 13, 7)          # 3, matching the worked example
pow(5, 10**18, 10**9+7) # instant, despite the huge exponent
```

**2. Inverses.** Since Python 3.8, a power of minus 1 computes the modular inverse:

```python
pow(4, -1, 11)   # 3, because 4 x 3 = 12 = 1 mod 11
```

**3. A toy discrete logarithm.** Find x such that `3^x mod 1000003 = 123456` by brute force, and time it:

```python
p, g, h = 1000003, 3, 123456
x = next(x for x in range(p) if pow(g, x, p) == h)
print(x, pow(g, x, p))
```

This finishes in a second or so because p has only 7 digits. Each extra digit multiplies the work by about ten. At 925 digits, the size of a 3072-bit prime, brute force is hopeless, and even the cleverest known methods are far out of reach.

**4. Toy RSA.** Build and break RSA with tiny primes:

```python
p, q, e = 61, 53, 17
n, phi = p*q, (p-1)*(q-1)
d = pow(e, -1, phi)          # private exponent
c = pow(42, e, n)            # encrypt 42
print(pow(c, d, n))          # decrypt: 42
# now break it: factor n by trial division
print([f for f in range(2, n) if n % f == 0][:2])
```

Factoring 3233 is instant. That is the whole security argument of RSA in miniature: everything rests on n being too large to factor.

## Chapter summary

- Modular arithmetic keeps numbers a fixed size and scrambles input-output relationships. Fast exponentiation makes huge powers practical, and must be constant-time in real code.
- Multiplying primes is easy; factoring their product is believed hard. RSA rests on this.
- Groups give a closed world for repeated operations. In well-chosen groups, finding the discrete logarithm is believed hard. Diffie-Hellman rests on this.
- Elliptic curves give a group where the discrete logarithm is much harder, allowing much smaller keys.
- All of these fall to large quantum computers. Lattice problems such as Learning With Errors are the main replacement.
